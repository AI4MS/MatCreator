Implementation date: 2026-11-13. Base: `4989f1b` via `codex/implement-aidb-20261113`.

## Delivered boundary

`matcreator.aidb.service.SessionAIDB(workspace, session_id)` owns one durable binding below `.aidb-sessions/<sha256(session_id)>`, including in a shared workspace. `bind(config_path)` records the selected config and its digest. `query(conditions)` calls installed `ai-ready-db/scripts/aidb_ops.py`, verifies complete receipts, report conditions, counts, artifact paths and unique IDs; `detail(record_id, binding_id=...)` rereads by ID. Changed bindings/configs invalidate old result actions. It does not create databases or write material records.

Native formula/element/method/label filters retain the installed interface semantics. Crystal role, spacegroup and setpoint temperature are explicitly separate host filters, applied only after a complete native query. Unknown, unsupported, incomplete, failed and zero-result cases stay distinct. Source XML digest plus frame index folds same-frame copies; records without this evidence remain individually visible and unverified. Independent runs are not collapsed by formula or calculation settings.

`publish(result)` persists full evidence and returns a compact `kind: aidb_result` reference. `result(result_id)` resolves that reference with its binding check. Later tickets can reuse this for candidates and completed records. `matcreator.tools.aidb_tools` registers `aidb_query`, `aidb_detail`, `aidb_bind` on both normal planning and step execution agents, inherits the parent session identity, discovers the installed skill, and chooses an explicit configured AIDB config once per chat. `web/aidb_api.py` serves result snapshots and fresh details under the session/owner path.

`web/vite-frontend/src/features/aidb/records.js` renders the same summary columns and complete detail sections as the clean baseline's `live-aidb.body.prototype.html`, including MatterViz structure previews, initial/final structure roles, expandable objects/arrays, units, provenance and missing states. Both timeline and delegated step tools render the shared result reference. Details reread on every opening and remove previous content on failure. Natural-language detail uses the same presenter and fresh-read path. Ticket 02 can pass `onExport` to `createAIDBResult`; export is visibly disabled until connected. Detail never selects a candidate or submits/writes a calculation.
