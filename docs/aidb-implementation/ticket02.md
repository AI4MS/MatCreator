# Ticket 02 — record exports

The normal chat tool `aidb_export` and the result-row action share `SessionAIDB.export(record_id, formats, result_id=..., binding_id=...)`. The row action validates membership in the result snapshot and checks that the binding still matches the session. Each export reads the record anew by ID, checks the binding after the read and before publishing, and persists the receipt and file data under the session export directory. The download route checks the binding again. The row click starts the EXTXYZ download when available and shows links for the available files. Neither export path submits calculations or writes material records.

EXTXYZ contains the final frame's elements, atom order, cell, coordinates, periodic boundaries, cell-total energy and per-atom forces. It declares `energy_unit=eV`, `energy_basis=cell_total`, the recorded `energy_definition` and `force_unit=eV/Angstrom`. dpdata 1.1 expects `eV` as the unit. Missing energy definition, invalid energy, or absent or invalid forces leave POSCAR and HTML available. Stress requires a valid frame index, a symmetric tensor in eV/Å³ and the tensile-positive convention. A supplied virial must agree with `−Vσ` before it is included with stress. Missing tensors remain absent. POSCAR preserves the site sequence. The standalone HTML contains the prototype detail sections, full record JSON, units and source evidence.

The service returns a compact `kind: aidb_export` receipt with `record_id`, `session_id`, `binding_id`, `export_id`, `status`, format-keyed `files` and format-keyed `issues`. Status can be `complete`, `partial` or `unavailable`. The normal chat tool adds `user_id` for the presenter. Ticket 06 connects and verifies this same capability on calculation-completed rows.
