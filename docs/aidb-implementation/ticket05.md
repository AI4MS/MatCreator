# Ticket 05 — VASP relaxation choice before Batch Job submission

The managed Bohrium Batch Job tool checks the prepared VASP relaxation directory before calling its existing submit service. It reads the actual INCAR, POSCAR, KPOINTS and POTCAR and recognizes the documented launcher and plain MPI VASP command. Formula and calculation type go to the installed AIDB reader. A candidate needs trusted admission, the tracked input digests, independent XML/OUTCAR completion and frame evidence, the actual starting structure, functional and U, spin and SOC, cutoff, regular k-point mesh and shift, potential identity, and valid EXTXYZ and POSCAR deliverables. A request for original raw outputs or additional artifacts follows computation. An unverified or unsupported input configuration remains eligible for normal authorized submission.

The choice journal binds the workspace, owner, session, originating graph/node, invocation, input revision, database binding, ordered record IDs and result ID. It survives reload. The ordinary chat can view, select, continue, revise or cancel. Browser detail open/reopen uses the existing fresh-by-ID route and does not resolve the choice. Selection rechecks the current staged revision and the selected record on the same fresh read used to generate the downloads. It delivers final POSCAR, per-cell energy and EXTXYZ. Continuation uses the original approved Batch Job path and matches its prior submission specification and input revision. The adapter rechecks the local revision after dry-run and before the final CLI call. This is local preflight evidence. A provider receipt connecting the uploaded bytes to the completed VASP run belongs to the receive workflow.

A complete zero result and query failure, timeout and incomplete receipt are separate internal outcomes. None publishes a candidate card or changes the original submit response. The per-record result snapshots and file receipts use the existing AIDB presenter and exporters. No VASP result write is performed by this ticket.

## Provenance contract

Tracked Batch Jobs that pass the relaxation input check persist `specification.vasp_inputs` with `sha256` (input names to SHA-256), `executable` and `launcher_sha256`. The provider's internal expected-revision parameter is checked at the submit boundary. To offer a recorded run for reuse, the reader expects `source_metadata.vasp_facts.source.submitted_inputs` with `provider`, `run_id`, `run_fingerprint`, `executable` and `sha256`. The attested run fingerprint must agree with the same record's independently checked output source. The historical Si positive test used the original staged file lineage for Bohrium job `d038dd1a453f4b7aa879b0cebf0607d9`. The licensed file is used locally. The repository and sanitized evidence carry its digest only.
